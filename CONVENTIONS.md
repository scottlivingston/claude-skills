# Conventions

Reviewable standards for the skills in this repo (per `skills/conventions`).

- **Contracts are cited, never restated.** Shared behavior lives in exactly one contract skill — `/finding-pipeline` for review-gate stages, `/hitl-questions` for questions put to the human, `/issue-tracker` for tracker operations, `/testing` for test recipes — and a skill that needs it cites the contract by name. A skill restating a contract's mechanics (cold-reader rules, escape hatches, domain-language rules, gate markers, validation stages, tracker verbs, test-recipe resolution) is a standards finding: replace the restatement with a citation. Local text is welcome only where the contract explicitly delegates — a gate's question classes and option shapes, an asking skill's cadence — or where it binds a contract rule to local terms in one line.
- **A contract is loaded where it's first followed.** The first step that acts under another skill says *load* it, per `/writing-for-agents`' skill mechanics — a name alone loads nothing. A skill named only for orientation is cited, not loaded.
- **Contract supremacy.** When a consumer skill and its contract disagree, the contract wins — the fix edits the consumer, never forks the contract.
- **Every fact has one owner.** A rule, list, or format is written once, in the file that owns it, and pointed at everywhere else. A SKILL never copies its workflow template's prompts, slot list, or tier assignments — it says what each stage is for and leaves the words to the template. A rule never names the skills that consume its output or describes how they read it; that is the consumer's to say. A rule stated in several skills lives in the one whose subject it is.
- **Outcomes, not mechanics.** Say what must be true, not the commands that make it true — a capable agent knows how to revert a commit, check a clean tree, or open a pull request. Spell out a step only where agents would otherwise vary and the variance hurts (an ordering with consequences, a default direction on failure, a trap the obvious approach falls into).
- **One clause of why.** A rule carries at most one clause of reason, and only when it changes a call at the margin. No failure stories re-arguing a rule an agent would follow on the rule alone, and no arguing the same default twice.
- **Plain words before terms.** Coin a bolded term only for a concept other skills must reference by name or a state the tracker records. An idea plain words carry stays in plain words.
